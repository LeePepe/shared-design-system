# Strata · 岩层 — v0.2 主题规则

状态：视觉方向已于 2026-10-16 接受；本次只记录主题规则，原生实现尚未落地。

这里的 v0.2 是主题验证版本，不是 NativeDesignKit 的包版本或发布声明。规则用于后续组件的视觉设计与审查；不新增 API、组件、token 数据、依赖或产品接入，也不替代既有实施任务的规格与审核流程。

## 设计目标

用同一套结构验证五组配色的气质：潮汐蓝、青苔绿、蔷薇粉、麦芽黄、鸢尾紫。配色受经典 iMac / iPhone 5C 启发，属于自定义设计，不是 Apple 官方设计系统。v0.2 接受的方向是圆润、克制的 Glass：中性底色、明度分层、少量糖果强调色、通透外壳和清晰的内容。

- 大面积使用低饱和中性色，品牌色用于主要操作、色板和少量强调。
- 同一组件在不同配色、明暗和材质下保持结构与尺寸一致；主题切换不制造布局跳动。
- 页面、内容区域、卡片主要通过明度和材质密度区分。内层边缘弱于外层，避免层层描边。
- 不使用霓虹、重阴影、动态光斑、鼠标追随折射或大面积装饰渐变。渐变只承担轻微材质高光。

## 颜色角色

| 职责 | 规则 |
| --- | --- |
| 表面 | 区分页面、区域、卡片、内嵌面、悬停面和选中面；不同品牌可搭配轻微不同色温的中性底色。 |
| 文字 | 主文字与辅助文字分别校准。普通文字对实际显示背景的对比度目标至少 4.5:1，包含透明材质合成后的背景。 |
| 品牌 | 糖果原色用于色板与小面积强调；主按钮采用对比度合格的实色及文字配对，不直接给浅糖果色配白字。 |
| 状态 | 成功、警告、错误等语义独立于品牌。使用符号或文字共同表达，不能仅靠颜色。 |
| 图表 | 独立管理图表色；品牌切换不隐式改变业务系列或状态含义。 |
| 边缘与焦点 | 装饰边缘轻于内容；键盘焦点清楚、连续可见，不能依赖微弱高光。 |

明暗主题分别校准，不能机械反色。深色主操作可使用浅品牌色与深文字；深色背景、辅助文字和材质密度必须单独检查。

这些是视觉职责，不是新 token ID 或公共枚举的声明。现有 `NativeStatusTone` 的计划范围和已发布 `DesignTokens` 可用值不因本文自动扩展。

## 圆角、尺寸与节奏

| 项目 | v0.2 网页参考基线 |
| --- | --- |
| 普通控件圆角 | 16px |
| 内容卡片圆角 | 24px |
| 外层容器圆角 | 32px |
| 按钮、分段选择器 | 胶囊轮廓 |
| 色板 | 圆形 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32px |
| 字号 | 正文 14px、标题 32px、分区标题 18px、辅助信息 11–12px |
| 控件可见高度 | 40px |

嵌套时按 32 → 24 → 16 的关系收敛，留出足够内边距，不用增大圆角挤压内容。窄屏内容卡片采用单列，参考内边距 16px、卡间距 12px。元信息需频繁阅读时，应优先提升可读性，而不是为了紧凑继续缩小字号。

上述 px 值记录已接受的网页比例。SwiftUI 使用语义字体并支持 Dynamic Type；尺寸按平台单位、命中区域、键盘交互和布局密度单独验证，不能把 14px 字体或 40px 高度当作所有原生平台的固定限制。原型的 1232px 最大内容宽、双列工作台和 420px 单列断点属于展示布局，不是库组件的页面结构要求。

## Glass 与实底

外层材质表达通透感，内层阅读面更实。正文、输入内容和标签保持清晰，不把透明度应用于整个内容视图；不叠加多层背景模糊。

| 网页材质参考 | 浅色 | 深色 |
| --- | --- | --- |
| 外层面板填充不透明度 | 62% | 72% |
| 内层内容填充不透明度 | 70% | 82% |
| 中性控件填充不透明度 | 64% | 85% |

网页原型使用 24px 背景模糊、125% 饱和度、细边缘、顶部高光和低强度接触阴影；深色外层与内层白边不透明度约为 16% / 9%。静态背景色形只作为辨识通透材质的线索，手机强度为桌面的 65%，不能抢过标题或主要操作。

这些是网页校准记录，不是跨平台相同效果的承诺。原生实现应使用目标系统可用的 SwiftUI 材质能力；不得把 CSS 的 blur / saturation 视为等价的原生 API，也不要求升级最低系统版本或实现 Liquid Glass 折射。Glass 用于合适的外层或浮动表面；不把每张内容卡、表单、开关和标签都变成独立玻璃层。

实底是同一主题的可读性回退：保留配色、布局、圆角和状态语义，关闭背景色形、模糊、材质高光及装饰阴影。减少透明度或系统能力不足时使用实底，不把实底截图标为 Glass。材质与明暗选择是不同维度；处理无障碍偏好不能隐式改成另一个明暗主题或默认品牌。

## 组件状态与动效

- Button 用样式区分 Primary、Secondary、Ghost；加载时有文字反馈并阻止重复触发，禁用态确实阻止操作。主按钮保持实色，次级操作采用中性材质，轻量操作不加多余阴影。
- Card 区分标题、正文、辅助信息和操作；示例统计明确标记为模拟数据。组件不接管真实业务含义或数据。
- List 的普通选中项以中性表面明度为主，并显示勾号和「已选」等非颜色标识；悬停、选中和键盘焦点各有清楚反馈。
- 状态变化保持尺寸稳定。网页短反馈参考 140ms；原生按平台行为适配。尊重 Reduce Motion，停止非必要动画，加载仍保留可读状态。

Button、Card、List 是这次主题验证的观察对象，不因此增加一批组件实现任务，也不撤销其他组件的既有计划。

## 参数归属与实施边界

- `shared-design-tokens` 是颜色数据的唯一来源。NativeDesignKit 继续使用精确版本的 `DesignTokens`，显式传入主题，原样传播 token 错误；不增加本地颜色表、默认主题、fallback token 或跨调用主题缓存。
- 本文的尺寸、材质和角色名称是设计规则，尚未成为 provider 的数据契约。后续若需新增共享风格参数，先通过 provider 的规格、发布和消费者升级流程；本次不改 provider，也不改当前精确依赖。
- 当前 v1 规格允许的小范围内部布局常量和系统语义字体继续有效；本文不要求在现有任务中偷偷更换依赖或复制一份 token 表。需要改变已审规格、API 或参数归属时，在对应实施 PR 明确处理。
- 公共 API、`ai/` 消费契约、版本与发布状态保持现状。主题方向的接受不等于原生组件、无障碍、最低系统版本或生产接入已验收。

## 后续原生实现的视觉验收

1. 保持同一布局，覆盖 provider 实际支持的配色、明暗、Glass 与实底；尚未支持的五色选择明确列为缺口，不伪造映射。
2. 使用当前 SwiftUI 实现的真实运行截图，区分正常材质与回退；网页截图只作为方向参考。
3. 检查文字裁剪、重叠、长文本、Dynamic Type、窄窗口、操作命中范围及实际合成背景的文字对比度。
4. 验证按压、加载、禁用、悬停、选择、键盘焦点及减少动态效果／透明度；静态截图不替代交互证据。
5. 证据绑定实际源码版本与平台，由独立 reviewer 审查；代码和依赖继续按现有仓库门禁交付。

方向依据为已接受的网页原型提交 `b4bff430517ed2e2944f814d8b5ab89a1866ee33`；[同版本真实截图](https://github.com/LeePepe/leepepe.github.io/tree/25a8d92e655d0be740c64174fcf63235357188fe/strata/v0-2)用于追溯视觉参考，不是原生测试证据。
